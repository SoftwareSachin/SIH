Nice — below is a **ready-to-run, step-by-step recipe** (CLI + snippets) to create a **service account JSON key** and use it from your backend to access Google Earth Engine (GEE). I’ll mark the places where you must substitute your values (PROJECT\_ID, SA\_NAME, etc.). I’ve also included short troubleshooting/security tips at the end.

> Prereqs: install & configure **Google Cloud SDK (`gcloud`)** and be logged-in as a user with Owner / IAM permissions on the target project. Also make sure you already have an Earth Engine account (sign up at earthengine.google.com if needed). ([Google for Developers][1])

---

# 1) Pick / create the Cloud project & set it as active

```bash
# replace with your project id (must be globally unique)
export PROJECT_ID="my-gee-project-12345"

# if you need to create a project (requires appropriate billing/org permissions)
gcloud projects create $PROJECT_ID --name="My GEE Project"

# or simply set an existing project as active
gcloud config set project $PROJECT_ID
```

# 2) Enable Earth Engine API (and Service Usage)

```bash
gcloud services enable earthengine.googleapis.com --project=$PROJECT_ID
gcloud services enable serviceusage.googleapis.com --project=$PROJECT_ID
```

(Enabling the Earth Engine API on the Cloud project is required so service accounts in that project can access GEE.) ([Google for Developers][1])

# 3) Create a service account

```bash
export SA_NAME="ee-backend"
gcloud iam service-accounts create $SA_NAME \
  --display-name="EE backend service account" \
  --project=$PROJECT_ID

# form the email (used later)
export SA_EMAIL="${SA_NAME}@${PROJECT_ID}.iam.gserviceaccount.com"
echo "Service account email: $SA_EMAIL"
```

# 4) Grant the right IAM roles to that service account

Minimum roles commonly required for programmatic access:

* **Earth Engine Resource Viewer** (`roles/earthengine.viewer`) — required for computations/reads.
* **(Optional)** Earth Engine Resource Writer (`roles/earthengine.writer`) — if you will write assets.
* **Service Usage Consumer** (`roles/serviceusage.serviceUsageConsumer`) — sometimes required for REST/API usage.

Example commands:

```bash
# viewer (required for read/compute)
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/earthengine.viewer"

# (optional) writer if you need asset writes/uploads
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/earthengine.writer"

# service usage consumer
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/serviceusage.serviceUsageConsumer"
```

(Exact role names: `roles/earthengine.viewer`, `roles/earthengine.writer`, etc.) ([Google Cloud][2], [Google for Developers][1])

# 5) Create and download the private key JSON

```bash
# create key and save locally (do this only once — store securely)
gcloud iam service-accounts keys create ./ee-service-key.json \
  --iam-account="$SA_EMAIL" \
  --project=$PROJECT_ID

# restrict file permissions
chmod 600 ./ee-service-key.json
```

(That JSON is the secret your backend will use — **never commit** it to a public repo.) ([Google for Developers][1], [Google Cloud][3])

# 6) Ensure your Cloud project is registered with Earth Engine

Open the Earth Engine project registration page and register the Cloud project if not already registered:

* Console: `https://console.cloud.google.com/earth-engine`
  (You can also register via the Earth Engine sign-up / project registration flow in the GEE docs.) All service accounts inside a registered Cloud project get access if they have the proper IAM roles. ([Google for Developers][1])

# 7) Use the key from backend — Python examples

**A. Using Earth Engine Python client (recommended for ee library calls)**
Install:

```bash
pip install earthengine-api
```

Code:

```python
import ee

SERVICE_ACCOUNT = 'ee-backend@my-gee-project-12345.iam.gserviceaccount.com'
KEY_PATH = '/path/to/ee-service-key.json'

# Use the ee helper that supports service account keys
credentials = ee.ServiceAccountCredentials(SERVICE_ACCOUNT, KEY_PATH)
ee.Initialize(credentials, project='my-gee-project-12345')

# test
print(ee.Image('COPERNICUS/S2/20210701T083601_20210701T084302_T36NXM').getInfo()[:100])
```

If `ee.Initialize` succeeds, your service account is correctly configured. ([Google for Developers][1])

**B. If you need a raw OAuth access token (for REST calls)**

```python
from google.oauth2 import service_account
from google.auth.transport.requests import Request
import requests

SCOPES = ['https://www.googleapis.com/auth/earthengine']

creds = service_account.Credentials.from_service_account_file(
    './ee-service-key.json', scopes=SCOPES
)
creds.refresh(Request())
access_token = creds.token

# Example: call Earth Engine REST endpoint (replace URL with specific endpoint)
headers = {'Authorization': f'Bearer {access_token}'}
resp = requests.get('https://earthengine.googleapis.com/v1/projects/earthengine-metadata/someEndpoint', headers=headers)
print(resp.status_code, resp.text[:200])
```

(Use `google.oauth2.service_account` to create a credentials object, refresh it to obtain an access token, then use `Authorization: Bearer <token>` for REST requests.) ([Google for Developers][4], [Google Auth][5])

# 8) Common gotchas & troubleshooting

* **Clock skew / `invalid_grant`**: If you see `invalid_grant` errors, sync the machine time (NTP). OAuth tokens are time-sensitive. ([Google for Developers][1])
* **CLI vs Python**: `earthengine` CLI (the `earthengine` commands) may still require `earthengine authenticate` (user OAuth). Service account JSON works for the Python client and REST calls, but some CLI operations (like `earthengine upload`) historically required additional flows. Test your workflow. ([GIS Stack Exchange][6], [Google for Developers][1])
* **Missing permissions**: If you get 403s, ensure the service account has `roles/earthengine.viewer` (minimum) and optionally `roles/earthengine.writer` for writes. ([Google Cloud][2])

# 9) Security best practices

* **Never** commit the key JSON to source control.
* Store the key in a secret manager (e.g., **Secret Manager**, or environment-specific secret store).
* Rotate keys periodically and remove keys you’re no longer using. ([Google Cloud][3])
